# PHP Hosting Deployment Layout

The Astro build contains static pages and the PHP contact-form endpoint. Deploy it to a PHP-enabled web host that can execute the endpoint.

## Project Layout

```text
agency-template/
├── public/
│   └── send-inquiry.php       # Copied into dist by Astro
├── private-config/
│   └── smtp-config.php        # Reads SMTP_PASSWORD from the environment
├── PHPMailer-master/
│   └── src/                   # PHPMailer dependency
└── dist/                      # Generated by pnpm build
```

Keep `private-config/` and `PHPMailer-master/` outside `public/`. Astro copies the endpoint from `public/` into `dist/`, but does not copy the private config or PHPMailer library.

## Hosting Layout

Upload the **contents** of `dist/` to the PHP host's document root. For a host using `public_html`, deploy this structure:

```text
hosting-account/
├── public_html/                # Web root: contents of dist/
│   ├── send-inquiry.php
│   ├── index.html
│   └── ...
├── private-config/
│   └── smtp-config.php
└── PHPMailer-master/
    └── src/
```

The endpoint looks for `private-config/` and `PHPMailer-master/` beside the web root. Keep both outside `public_html` so they cannot be requested directly from a browser.

## Deploy

1. Run `pnpm build` from the project directory.
2. Upload the contents of `dist/` to the PHP host's web root, not into a nested `dist/` directory.
3. Place `private-config/` and `PHPMailer-master/` beside the web root on the server.
4. Set `SMTP_PASSWORD` in the hosting environment. Use a rotated credential and never commit it in a file.
5. Confirm PHP is enabled and outbound SMTP over port 465 is permitted. Submit a test inquiry and verify it reaches the configured inbox.
6. Replace the placeholder domain in `astro.config.mjs` with the production domain before the final build.

The Astro development server does not execute PHP. Test the contact form on the PHP host after deployment.
